x402-notify

Real message delivery, billed per message — Telegram bot messages and SMTP email, each with the delivery receipt returned inline. Every paid route answers an unpaid request with 402, then returns the purchased artifact in the body of the same request once you retry with an X-PAYMENT header.

Paid routes

RoutePriceReturns
POST /telegram $0.002 The delivery receipt: message id, chat, and the timestamp Telegram accepted it.
POST /email $0.002 The SMTP acceptance receipt: message id, accepted and rejected recipients.

GET /health and GET /.well-known/x402 are free and unauthenticated.

Pay for one call

curl -s -X POST "$BASE/telegram" -H 'content-type: application/json' \
  -d '{"chatId":"@your_channel","text":"deploy finished"}'   # 402 + accepts[]
# then retry the same request with an X-PAYMENT header, or let x402-fetch do it

The 402 challenge carries the call schema for the route it guards (accepts[].outputSchema.input / .output), so an agent that has never read this page can still invoke the endpoint correctly.

Payment

  • USDC on Base (EIP-3009) or Solana (SPL transfer, facilitator-sponsored fees) — your wallet picks the rail.
  • Charged per request. No account, no API key, no subscription.
  • Settlement receipt returns in the X-PAYMENT-RESPONSE header and in the response body.
